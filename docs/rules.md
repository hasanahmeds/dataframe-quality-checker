# Rules and report semantics

Required columns default to true; nullable defaults to true. An optional missing column is skipped; an optional present column is checked. Extra columns fail unless allow_extra is true. min_rows defaults to one; explicitly set zero to allow a header-only/empty frame. Empty-series missing fraction is zero. max_missing is inclusive. Unique-column checks exclude nulls and count all rows in a duplicate group. unique_rows includes missing values using pandas duplicate semantics.

Types are semantic, not exact pandas dtype matches: integer accepts finite integral real numbers (including 1.0), but excludes booleans and numeric strings. number accepts finite real values, excluding bool. string requires strings; boolean requires actual bool values; datetime accepts valid scalar timestamp/date objects or parseable strings, not numeric epoch values. Datetime strings are interpreted by pandas; use ISO-8601 in source data to avoid ambiguous dates. Missing values are checked independently by nullable/max_missing.

Numeric bounds are inclusive. Regex uses Python fullmatch and checks strings only; wrong types fail the separate type rule. Allowed categories use scalar membership; the type rule distinguishes booleans from numbers. Invalid numeric types and nonfinite numbers fail type checks and are excluded from range/outlier calculations.

IQR: Q1/Q3 use NumPy linear quantiles; points outside Q1-k*IQR and Q3+k*IQR are warnings. If IQR is zero, fences coincide, so values different from that fence can be flagged. Z-score uses population standard deviation (ddof=0), absolute score > threshold, and scaled values to reduce overflow. Constant data produces no z-score outliers. Both methods default to at least five finite observations. Too few observations produce a passed check with an explicit skipped message. Outliers are heuristic flags, not proof of incorrect records. Thresholds are configurable; do not tune them solely to force data to pass.

Reports contain one entry per evaluated rule. failed_count is rows affected by that rule, except schema structure rules, where it is 0/1 per field or condition. Counts can overlap across checks and must not be summed as unique bad rows. evaluated_count is the relevant row count (or finite sample count for skipped outlier checks, or 1 for structure conditions). sample_positions are zero-based physical row positions, not DataFrame index labels; raw values are omitted. failed_error_checks and failed_warning_checks count failing rules. passed depends only on error checks. CLI --fail-on-warning changes exit status, not report passed.

The checker never drops, fills, coerces, reorders or modifies user data. CSV ingestion uses pandas inference and its default NA vocabulary (including empty fields and NA-like strings). For precise nullable types or literal NA strings, construct a DataFrame in Python with explicit read_csv options and use the library API. Nested list/array/object-valued cells are unsupported. Regex patterns and schemas are trusted configuration; adversarial patterns may be expensive.

Reports include no run timestamp, so identical inputs/schema produce deterministic output. CSV stores one row per check, not global summary fields. JSON is the complete report. Existing report files are atomically replaced; inputs/schema paths are protected. The parent output directory must exist.
